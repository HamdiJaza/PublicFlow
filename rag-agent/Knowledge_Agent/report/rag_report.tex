\heading{1. What RAG does and what was implemented}
Retrieval-augmented generation (RAG) first searches a knowledge base, then gives the
retrieved passages to a language model to answer a question. Here, the Knowledge Agent
provides documented municipal contacts or procedures after an incident is identified.
Updating a source updates the knowledge base after reindexing; it does not retrain the model.

\begin{center}\small
Request $\rightarrow$ BGE-M3 query vector $\rightarrow$ Qdrant search and filters\par
$\rightarrow$ selected source passages $\rightarrow$ Qwen answer $\rightarrow$ JSON validation
\end{center}

\subheading{Engineering choices and parameters}
{\small
\begin{tabularx}{\linewidth}{|L{27mm}|Y|}\hline
\textbf{Choice} & \textbf{Implementation and justification}\\\hline
RAG type & Single-stage dense retrieval followed by generation. It keeps the small multilingual prototype inspectable. No lexical/hybrid superiority comparison was conducted.\\\hline
Embedding model & BGE-M3 dense, 1,024 dimensions, normalized vectors and cosine similarity. Retained for French/Arabic semantic retrieval; dialect quality is not established by the model name. The corrected implementation uses Ollama embeddings.\\\hline
Vector store & Embedded Qdrant: metadata filtering and persistence without another server. Local storage is opened by one process; stop the API before direct indexing/evaluation.\\\hline
Top-$k$ and filters & $k=3$ limits context while allowing alternatives. Exact category filter, except \code{NONE}, which searches all categories. No reranker: another model has no measured benefit here.\\\hline
Score cutoff & Shared API/evaluator threshold 0.40; filter before building both context and citation candidates. It is a working setting, not calibrated answer confidence.\\\hline
Generation model & Existing local \code{qwen2.5:3b} permits tests without an external key. No quality comparison with the original Groq model was verified; no training or fine-tuning was performed.\\\hline
Generation controls & Temperature 0 reduces sampling variation; seed 42 is an arbitrary fixed control. Context 8,192 and output cap 512 accommodate short inputs and JSON answers. No parameter sweep established optimal values.\\\hline
\end{tabularx}}

\heading{3. Prompt engineering: iterations, results and critique}
The key prompt answers a question using sources. Versioned files are in \code{prompts/knowledge/};
the separate library \code{prompts/README.md} records techniques, failures and changes.
V1/v2 have no saved executions.

For v3--v7, \promptcalls{} actual Ollama calls use the page-2 controls and five fixed
full-document contexts. One attempt per condition, no retries; v3/v4 order alternates by case.
Later versions reuse the cases after inspecting failures. These tests bypass retrieval
and have no held-out evaluation.

\input{generated/prompt_versions.tex}

Counts use each study's validator. Checks cover schema, answerability, null deadline and
required digits, missing language errors. After v6, validation was tightened: its quoted-null
Arabic answer also fails the current schema (v6: 1/5 instead of recorded 2/5).
JSON mode and validation are runtime controls. No chain-of-thought, voting or tree search was used.

\subheading{Before/after findings and current decision}
V3's unsupported 72-hour/1300 demonstrations are replaced by source-backed examples in v4:
an inspected defect is corrected, but P02 changes from contact to refusal. V5 restores P02
while P05 changes from refusal to false details. V6 introduces quoted-null errors.
V7 restores the French contact, refuses Arabic diagnosis and invents an integer deadline
that validation rejects. V4 remains the conservative provisional default; its contact-refusal
and language failures remain unresolved. The later versions do not establish an overall improvement.

\subheading{Corrections, evidence and remaining validation}
API/evaluation share one cutoff and selected context/citation set. Strict types and a
context-based deadline check reject invalid outputs; they do not verify every claim.
Five offline contract tests pass. Fingerprints guard against stale vectors. Raw runs,
settings and critiques are under \code{evaluation/prompt_*} and \code{evaluation/prompt_review.csv}.

The corrected index, live retrieval/HTTP tests and n8n execution remain unverified:
BGE-M3 download failed; its tokenizer and Qdrant dependency are unavailable.
The \code{POST /knowledge} code is implemented. This component report does not establish
end-to-end operation or cover the other agents.
