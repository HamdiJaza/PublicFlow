# Vision v11: extract a claim, then check its positive condition

**Executable prompts:** unchanged [v2.txt](v2.txt) plus [severity_v1.txt](severity_v1.txt) for the image pass; [v11_claim.txt](v11_claim.txt) for text extraction; [v11_verify.txt](v11_verify.txt) for visual verification.

**Role and techniques:** conditional prompt chaining. Image-only zero-shot analysis supplies category and observations. A text-only extraction role uses explicit criteria, abstention and three short text/target examples (few-shot) to separate non-claims, positive conditions and explicit negation. A zero-shot visual verification role checks only that positive condition against the original pixels. No reasoning transcript, voting, training or new model is used.

**Observed failures:** v9 correctly handles vague requests but rejects matching branches text because its notes omit branches. V10 recovers the matching result but accepts both vague requests and the denial of rubbish. Combining those stages unchanged would still fail. V11 therefore separates claim extraction from presence verification, removing original negated wording and incomplete notes from the final visual question.

**Output contract and composition:** CaptionClaim returns kind, positive condition, negated and reason. NO_CLAIM/UNVERIFIABLE text produces null plus its explanation. CLAIM proceeds to VisualCondition, returning PRESENT/ABSENT/UNVERIFIABLE from the photo. An unverifiable condition maps to null; otherwise agreement is presence with explicit negation applied. Python follows these declared model outputs; it has no keyword, translation or length classifier. The raw extraction and presence decisions remain saved.

**Runtime:** one call without a caption, two for non-checkable text, up to three for a concrete claim. Preserve the initial category, severity, description, evidence and visual confidence. Only consistency and inconclusive-caption explanations are composed. A failed stage fails the whole request. Schema changes and conditional call flow make this a configuration study of chaining, not an isolated wording effect.

**Evaluation:** [frozen protocol](../../evaluation/vision/claim_gate/protocol.md), same six development conditions, one pipeline each; controls explicitly reused from v6. The actual known caption appears in an example, so success is a regression correction rather than independent language accuracy. Visual descriptions may remain incomplete, extraction can mishandle compound claims, and absence requires a clear view. No broader image-category or language improvement is claimed.

**Measured outcome and decision:** six pipelines, fourteen actual model calls; 6/6 comparison targets, 2/2 vague explanations and 6/6 category/severity targets. Visual review found no new material regression relative to the unchanged image baseline. V11 is used by `/vision`. [Metrics](../../evaluation/vision/claim_gate/metrics.json), [review](../../evaluation/vision/claim_gate/review.csv), [decision](../../evaluation/vision/claim_gate/decision.json).

**Remaining observed error:** T05 retained its clear-ground/no-branches wording with `negated=false` instead of fully normalizing the denial. The verifier returned ABSENT, giving the correct final false result. No generated case exercised `negated=true`; compound negation is not validated generally. Initial branch underdescription and irrelevant image uncertainty remain. This correction concerns caption comparison, not all visual failures.
