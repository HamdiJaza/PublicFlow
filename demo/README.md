# Demo complaints

Ready-to-use complaints for testing the citizen portal (`http://127.0.0.1:8090/`).
Each folder in `cases/` holds the file(s) to upload, `description.txt` (the text to paste, when the case has one)
and `instructions.txt` (what to choose in the form and the expected result).

Sign in first, for example with the test citizen account (CIN `01234567`), then open **New complaint**.

## Accepted formats

| Evidence type | Files | Limits | Description |
|---|---|---|---|
| **Photo** | one JPG, PNG or WEBP image | 10 MB | required (at least 5 characters), unless a voice note is added |
| **Photo + voice note** | one image + one audio file (WAV, MP3, M4A, OGG, WEBM, FLAC) | image 10 MB; audio 2 min, 30 MB | optional: the transcribed voice note replaces it |
| **Video** | one MP4, WEBM or MOV video, sent alone | 1 min, 50 MB | optional |

Every complaint also needs **Your municipality** (Municipality of Tunis, Ariana or Ben Arous, grouped under *Greater Tunis*).
**Where is it?** is optional, up to 300 characters; the location is never guessed from the photo.
The description is limited to 3,000 characters. One complaint is processed at a time on this computer.

## What "My complaints" shows

One line per complaint sent with your account, newest first:

| Field | Example |
|---|---|
| Problem type | Road damage, Street lighting, Waste, Water leak, or *Type not determined yet* |
| Status | Being checked by your municipality · Assigned to the team doing the work · Work in progress · Resolved · Rejected |
| Sent | date and time (Tunis time) and the team in charge once assigned |
| View details | opens the tracking page: history of every status, message from the team, summary, procedure if verified |

## The cases

| Folder | Type | What it tests | Expected result |
|---|---|---|---|
| `01-road-pothole-photo` | Photo (real) | normal road complaint | Road damage → municipal services |
| `02-road-damage-video` | Video (made from the real photo) | video path, 3 frames must agree | Road damage → municipal services |
| `03-street-light-out-photo` | Photo (synthetic) | routing to STEG, municipality without procedure corpus | Street lighting → STEG, needs review |
| `04-waste-pile-photo` | Photo (synthetic) | waste in Ben Arous | Waste → municipal services |
| `05-water-leak-photo` | Photo (synthetic) | routing to SONEDE | Water leak → SONEDE |
| `06-water-leak-video` | Video (synthetic, animated) | video without description | Water leak → SONEDE |
| `07-photo-with-voice-note` | Photo + voice note | transcription replaces the text | Waste → municipal services |
| `08-text-photo-mismatch` | Photo (synthetic) | text says water leak, image shows a street lamp | Needs review (mismatch) |
| `09-out-of-scope-bench` | Photo (synthetic) | a type the system does not handle | Needs review, the municipality decides |
| `10-invalid-format` | GIF file | input validation | Refused: format not supported |

**Be aware:** only cases 01 and 02 use the real demo photograph (`demo/road-damage.jpg`).
The other images and the leak video are simple **synthetic drawings** made by `make_demo_cases.py`; the Vision agent
may be less certain about them than about real photos, which itself leads to a *Needs review* result. For the most
convincing demo, also try your own real photos. The voice note is generated by the local Windows speech engine.
The expected results describe the intended routing; the AI outcome of each run is not guaranteed.

## Rebuild the cases

```
.runtime\nvidia-intake-venv\Scripts\python.exe -B demo\make_demo_cases.py
```

The script uses only local tools (OpenCV, FFmpeg, Windows speech); it downloads nothing and calls no AI service.
